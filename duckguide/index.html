FIELD NOTES / 01

Start here

Get the marsh running

Use Node.js 22 or newer on your server. From this directory:

bash
npm ci
cp -n .env.example .env
nano .env
npm test
npm start

On Windows, a blank .env is already supplied in the local project. Edit it in your IDE, then run npm start in duck-hunt. If installing from the ZIP, copy .env.example to .env first. npm ci should be run on the destination computer; the ZIP excludes platform-specific node_modules.

If SQLite needs compiler tools on Ubuntu:

bash
sudo apt update
sudo apt install -y python3 make g++
npm ci

Dashboard: https://duck.tinko.online/

OBS Browser Source: https://duck.tinko.online/?overlay=1

Health diagnostics: https://duck.tinko.online/health

The process stays running even when the page is closed. Keep the terminal/process manager running; Ctrl+C stops it gracefully. Run one instance per duck database.

FIELD NOTES / 02

Run with PM2 on Ubuntu

Keep your game online

First stop the foreground npm start process with Ctrl+C. Do not run two copies against the same port/database. From this game's directory, using the same shell and Node installation where npm start works:

bash
node --version
command -v node
pm2 delete duck
pm2 start ecosystem.config.cjs --only duck
pm2 logs duck --lines 60

pm2 delete duck replaces only the old PM2 process registration; it does not delete game saves or configuration. If that registration does not exist, continue to the start command. The supplied configuration pins the working directory and runs the current Node executable directly, matching npm start. It runs one instance and allows time for graceful shutdown.

Once the game is responding correctly, save the process list with pm2 save. For automatic startup after reboot, run pm2 startup and follow its printed command, then pm2 save. Use Node 22 or newer, and run PM2 as the same Ubuntu user that owns this game's private data. If you recently changed Node versions, make sure the PM2 daemon/startup service uses that installation too.

For a quick alternative, start the npm script itself from this directory:

bash
pm2 start npm --name duck -- start

Use one method, not both. If PM2 still fails, inspect pm2 describe duck and pm2 logs duck --lines 60 --nostream. A port-in-use message means another process is listening; module/ABI errors can indicate a different Node installation. Configuration errors can also come from environment variables cached by PM2; .env does not override existing process variables. Do not post .env or token values when sharing diagnostics.

Give your channel a connection

Edit this folder’s .env. Channel and account credentials start blank; nothing was copied from another game’s private configuration.

Startup verifies channel IDs when public lookup is available. Tokens stay on the server; the browser receives game state only. Keep .env and data/ private. Use a separate authorization when running another bot server at the same time, so rotating refresh tokens do not overwrite one another.

Replies use Kick’s official chat API ↗. Incoming chat uses the same unofficial web-client Pusher feed as the existing games, with reconnect, heartbeat and room filtering. All Kick connections are outgoing; no inbound webhook, public hostname or HTTPS listener is required. Missed chat during an outage cannot be replayed. A live Kick command/reply still needs to be checked after your credentials are configured.

Command overlap: Humidor Hunt also handles !hunt. If both listen to the same channel, that command can play both games. Pause one game or use different channels when you want only one to respond. No other game’s settings have been changed.

Commands

A few words. A whole marsh.

CommandAction
!huntAttract a duck with your decoys and attempt a catch with your shotgun.
!shotgun upgradeImprove shotgun success.
!blind upgradeShorten the cooldown between hunts.
!decoys upgrade / !decoy upgradeAttract rarer ducks. Both spellings work.
!sellducksSell all ducks in your bag, including band bonuses.
!moneyWallet, unsold bag value and lifetime sale earnings.
!gearLevels, upgrade costs, shotgun reliability, cooldown and decoy rarity odds.
!duckbagUnsold inventory summary. Full inventory is on your dashboard profile.
!duckcollectionPermanent species discoveries and banded finds.
!ducktopTop five hunters by lifetime sale earnings.
!duckhelpShort command guide.

Commands are case-insensitive. Click a command on the dashboard to copy it, then paste it into Kick chat. Gameplay follows the real sender’s numeric Kick ID. There is no browser endpoint to submit hunts or impersonate viewers.

The old !upgrade ... commands are ignored so the duck game does not respond to your other tool’s upgrade commands.

Everyone starts with $0 and level 1 gear. Hunting is free. Blinds set the per-player cooldown: 45 / 35 / 25 / 15 seconds at levels 1–4 by default. Failed hunts consume the cooldown; invalid syntax does not. A short 0.8-second command throttle limits rapid spam. Message IDs suppress replays for seven days. All player changes and events are saved together in a SQLite transaction.

Retrieved ducks go into the bag. Cash is awarded only when selling, so use !sellducks before buying gear. There is no bag capacity limit. Standard and banded variants are stored separately. Selling clears the bag but keeps every collection discovery. Dollars are fictional game currency.

Ducks, rarity and bands

Know what you’re chasing

The field guide contains all 34 supplied species at their exact base prices. Edit catalog.js to adjust future balance.

  • Legendary: Golden Mallard $10,000; King Eider $5,000; Harlequin Duck $4,500; Eurasian Wigeon $3,500.
  • Epic: American Black Duck $1,800; Canvasback $1,500; Cinnamon Teal $1,200.
  • Common / standard: all 27 supplied diving, sea and puddle ducks, $150–$750.
  • Species are equally likely within their tier. Decoy level sets the tier probabilities below. Shotguns and blinds never affect rarity; gear never changes band odds.
  • Every duck independently has a 0.5% chance to spawn banded. The metal band adds $10,000 on top of its base price. A banded Mallard sells for $10,350; a banded Golden Mallard sells for $20,000.
  • Band rolls happen before the shotgun check. If the gun jams, you receive no duck or band reward.

Any shotgun can catch any duck that appears. Decoys alone control which rarities appear. There is no combined gear-level requirement, no blind failure roll and no dog failure roll.

OBS overlay

Bring the hunt on stream

Add a Browser Source at https://duck.tinko.online/?overlay=1, width 1920, height 1080. The background is transparent and the card defaults to the bottom left.

Results and animations are independent. Every hunt immediately produces its own result card, showing the hunter, species, caught/escaped outcome, band and bag value. Cards display for eight seconds by default, with the latest five visible. New cards never wait for animations. During heavy traffic the oldest visible card gives way to a new one instead of adding to a queue. Sales, upgrades, help and cooldown notices stay in chat/dashboard and do not create hunt cards.

At most one hunter’s animation starts per 20 seconds by default. The first hunt after that interval receives the animation; hunts during the interval still get immediate result cards. There is no animation backlog: nothing starts later just because a previous hunt waited. The animation lasts nine seconds and the Labrador is decorative. Interval timing persists across server restarts and on/off controls. A connecting overlay joins still-active cards/animations without replaying expired ones. Off mode hides both immediately, and resuming does not redisplay old cards.

Optional URL settings:

text
https://duck.tinko.online/?overlay=1&position=topright&scale=1.2

Positions: topleft, top, topright, bottomleft, bottom, bottomright. Scale: 0.5–2. Cards shrink to fit smaller Browser Sources. Keep the OBS source at full canvas size for positioning.

Every hunt still counts when chat is busy. The dashboard keeps the latest sixty events. Chat replies are serial, spaced by one second by default, honor rate limits and expire after two minutes in a backlog. These display limits never undo saved results. If you set an animation interval shorter than the animation duration, the duration becomes the minimum spacing so animations cannot overlap.

Admin controls

Your marsh. Your controls.

Only the broadcaster and GAME_ADMIN_IDS may use:

text
!duck off
!duck on
!duck toggle
!duck mute
!duck unmute
!duck reset
!duck reset confirm CODE

Off state survives restarts. It stops gameplay, clears the visible overlay and mutes/cancels pending bot replies. The incoming feed stays open to recognize an authorized resume. Turning off confirms on the dashboard rather than posting a chat reply while muted.

Mute is separate from off. !duck mute silences only the bot’s outgoing chat replies: hunts, upgrades, sales, saves, dashboard and OBS events continue while the game is on. It cancels queued replies and aborts an in-flight request locally; a reply already accepted by Kick cannot be recalled. The mute command confirms on the dashboard without another chat reply. !duck unmute enables fresh replies without replaying anything from the muted period. Its confirmation can appear in chat when the game is on and BOT_REPLIES=true. Mute survives server restarts and on/off toggles. Admins can change the mute preference while the game is off; doing so does not resume the game. BOT_REPLIES=false still overrides chat output.

Reset first returns a fresh one-time code. The same admin must confirm within 60 seconds. Confirmed reset clears only duck players, money, bags, gear, collections, history and queued replies. It preserves .env, rotated credentials and the chat mute preference. No reset happens during installation or updates.

Restart the server after changing .env or application files, then refresh the page/OBS source. Player progress is in data/ducks.sqlite; rotated tokens are in data/tokens.json. Stop the server before copying the full private data folder for a simple consistent backup. Keep .env and data/ when updating. Never share them in a release ZIP.

Version 1.2 separates the three gear effects, retires/refunds dog upgrades, and replaces queued animations with immediate result cards and spaced animations. Replace the application files from the updated ZIP, keep your existing .env and data/, then restart the duck server and refresh the dashboard/OBS source. Dependencies are unchanged. The first startup automatically updates old saves and refunds dog gear in one transaction; it also discards the old animation queue. No player reset is needed. New .env settings are optional and use the defaults above when omitted.
